# Backend Music Quiz

Самостоятельный Go-репозиторий. Все команды ниже выполняются из этой папки.

## Команды

- `go mod download`
- `go test ./...`
- `golangci-lint run --config .golang-ci.yaml`
- `go build ./cmd/quiz`
- `docker compose up -d --build` — самостоятельный запуск.
- `docker compose --profile test run --build --rm test` — PostgreSQL, ffmpeg и race detector.
  Локальные интеграционные тесты требуют TEST_DATABASE_URL; без него они пропускаются.

## Код

- Пишите простой Go-код, небольшие функции и понятные имена. Соблюдайте .golang-ci.yaml.
- Русские godoc-комментарии обязательны для экспортируемых типов, функций и констант.
- SQL находится в репозиториях, бизнес-правила — в сервисах, HTTP-слой валидирует формы и вызывает сервисы.
- Репозитории объединены Unit of Work; атомарные изменения выполняются в транзакции.
  Не держите транзакцию во время внешних запросов и работы ffmpeg/yt-dlp.
- Используйте context.Context, таймауты, ограниченную конкурентность и корректную остановку горутин.
- Обрабатывайте ошибки; не используйте пустые обработчики и необъяснённые подавления линтера.
- Не добавляйте абстракции или DTO, если они не упрощают конкретную текущую задачу.
- Новые изменения схемы оформляйте новой миграцией; не меняйте уже применённые миграции.
- Меняя HTTP-контракт, обновляйте docs/openapi.json и README. Фронтенд — внешний потребитель API.

## Инварианты

Points: 0..100, по умолчанию 100; ноль исключает ветку из генерации. Выбор: исполнитель → альбом → трек.
Исполнитель не повторяется во всём пакете. Сохраняются только полные раунды по 10 вопросов.
Звуковые вопросы фиксируют trackStartSec/trackFinishSec: запись до 30 секунд — целиком,
иначе случайный интервал на 30 секунд. Повторное воспроизведение не меняет интервал.
Парсинг явно запускается через API, повторный импорт сохраняет пользовательские оценки и исправления.

Не выводите секреты из .env. Не делайте commit/push без разрешения пользователя.
