# Музыкальные квизы

Go + Gin + PostgreSQL. Сервис хранит музыкальный каталог, импортирует данные Genius,
дополняет их MusicBrainz, скачивает изображения и MP3 и составляет квиз-пакеты.
Авторизации нет; по умолчанию HTTP и опубликованный порт PostgreSQL доступны только локально.

## Запуск

Нужны Docker Desktop с Linux-контейнерами и токен Genius из https://genius.com/api-clients.

```powershell
Copy-Item .env.example .env
# Запишите GENIUS_ACCESS_TOKEN в .env.
docker compose up -d --build
```

API: `http://127.0.0.1:8080`. Проверки: `GET /health`, `GET /ready`.
SQL-миграции встроены в бинарник и применяются при запуске. PostgreSQL хранится в Docker-томе,
медиатека — в папке `../media`, подключённой к `/app/data`; путь можно переопределить QUIZ_MEDIA_DIR.
`docker compose down` останавливает сервисы, сохраняя данные.

Для запуска Go-приложения на ПК нужны Go 1.26+, PostgreSQL 17+, `yt-dlp`, `ffmpeg` и `ffprobe`
в PATH; для полной поддержки YouTube нужен Node.js 22+ (или Deno/Bun, выбирается через
`yt_dlp_js_runtime`). Docker-образ включает Node.js и пакет `yt-dlp-ejs`.
Утилиты запускаются напрямую через `exec.CommandContext`, поэтому PowerShell-функция
или алиас без соответствующего исполняемого файла не подходят. На текущем ПК EXE найдены.

```powershell
docker compose up -d db
$env:DATABASE_URL='postgres://quiz:quiz@127.0.0.1:15432/quiz?sslmode=disable'
$env:GENIUS_ACCESS_TOKEN='ваш-токен'
go run ./cmd/quiz
```

Локальный запуск Go не читает `.env` автоматически. ENV: `DATABASE_URL` обязателен,
`HTTP_ADDR` по умолчанию `127.0.0.1:8080`, `GENIUS_ACCESS_TOKEN` нужен для запуска парсинга.
Остальная эксплуатационная конфигурация хранится в единственной записи таблицы `settings`.

## Рабочий сценарий

```powershell
$base='http://127.0.0.1:8080/api/v1'
$artist=Invoke-RestMethod "$base/artists" -Method Post -ContentType 'application/json' `
  -Body '{"name":"Queen","tags":["rock"],"points":100}'
$run=Invoke-RestMethod "$base/parsing-runs" -Method Post
Invoke-RestMethod "$base/parsing-runs/$($run.id)"
Invoke-RestMethod "$base/albums?artist_id=$($artist.id)"
Invoke-RestMethod "$base/tracks?artist_id=$($artist.id)"
Invoke-RestMethod "$base/downloads?status=manual"

# Для пакета нужен хотя бы один полный раунд: 10 разных исполнителей с подходящими медиа.
$pack=Invoke-RestMethod "$base/quiz-packs" -Method Post -ContentType 'application/json' `
  -Body '{"name":"Рок-квиз","artist_tag":"rock","tags":["rock"]}'
Invoke-WebRequest "$base/quiz-packs/$($pack.id)/questions/1/audio" -OutFile question-1.mp3
```

Добавление исполнителя не начинает импорт. `POST /parsing-runs` ставит явный запуск в очередь,
работник обрабатывает исполнителей `created` и исполнителей с ошибками предыдущих запусков,
каждого не более одного раза за запуск. Статус `manual` исключает исполнителя из автоматической очереди.
Параллельный активный запуск запрещён (`409`).
Запуск `finished` может содержать ошибки отдельных исполнителей: проверяйте `failed`
и поле `error` исполнителя. Статус `parsed` с непустым `error` означает необязательные
предупреждения: например, MusicBrainz не нашёл однозначное совпадение или не получен полный треклист.

Из Genius берутся все доступные альбомы и их полные списки песен в `track_list` — CSV
с заголовком `position,title`. `track_list_complete` показывает полноту списка.
Отдельными Track сохраняются только топ-N песен исполнителя по популярности Genius:
`N = floor(k_parse × Points)`, по умолчанию `k_parse=0.1`. При положительном результате
настроек и Points минимум равен одному. При `Points=0` или `k_parse=0` импортируются только
сведения об исполнителе и альбомах. Изменение Points не удаляет ранее импортированные треки.

Трек сохраняется даже без звукового источника. Для него создаётся `unknown`-задача,
которая переходит в `manual`. Повторный парсинг использует внешние ID и не дублирует каталог
и известные источники. Пользовательские Points, теги, названия уже импортированных альбомов/треков
и ручные исправления страны, полного имени и состава группы сохраняются.

Официальный Genius API используется для поиска, исполнителей и песен. Альбомы и полные
треклисты требуют веб-API `genius.com/api`: он может изменяться или блокировать запросы.
При ответе 403 импортируются альбомы, указанные у популярных треков; их треклисты отмечаются неполными.
При HTTP 429 повторяется тот же запрос после ожидания: Retry-After учитывается как число секунд
или HTTP-дата. Без заголовка по умолчанию используются задержки 30, 60 и 120 секунд (три повтора).
Ожидание отменяется при остановке сервиса и ограничивается таймаутом обработки исполнителя.
После исчерпания повторов или времени запуск останавливается, текущий исполнитель остаётся в очереди.
Настройки: `source_429_retries` (0..10), `source_429_delay_seconds`, `source_429_max_delay_seconds`
(предел экспоненциальной задержки, не сокращает Retry-After). `genius_request_interval_ms` задаёт
минимальный интервал запросов Genius: по умолчанию 1000 мс. Новые настройки добавляются миграцией,
сохранённые пользовательские значения не перезаписываются.
Эта зависимость изолирована в адаптере. MusicBrainz работает с ограничением одного запроса
в секунду; при нескольких точных совпадениях поля остаются незаполненными. Их можно исправить PATCH-запросом.

## HTTP API

Все пути ниже имеют префикс `/api/v1`. Формальная спецификация: [docs/openapi.json](docs/openapi.json).
JSON использует `snake_case`, кроме явно согласованных `trackStartSec` и `trackFinishSec`.

| Метод и путь | Назначение |
| --- | --- |
| `POST /artists` | Создать исполнителя: `name`, необязательные `tags`, `points` |
| `GET /artists`, `GET /artists/{id}` | Получить исполнителей; список отсортирован от новых к старым, фильтры `tag`, `status` |
| `PATCH /artists/{id}` | Изменить поля исполнителя или статус на `manual` / `created` |
| `DELETE /artists/{id}` | Удалить исполнителя и каталог, если нет ссылок из вопросов |
| `POST /artists/{id}/retry` | Вернуть обработанного/ошибочного исполнителя в `created` |
| `POST /parsing-runs` | Запустить импорт асинхронно, ответ `202` |
| `GET /parsing-runs`, `GET /parsing-runs/{id}` | Состояние и счётчики импорта |
| `POST /albums` | Создать альбом: `name`, `artist_id`, необязательные `points`, `release_date` |
| `GET /albums`, `GET /albums/{id}` | Получить альбомы; фильтр `artist_id` |
| `PATCH /albums/{id}` | Изменить `name`, `points`, `release_date` |
| `DELETE /albums/{id}` | Удалить альбом; треки остаются без привязки к нему |
| `POST /tracks` | Создать трек: `name`, `artist_id`, необязательные `album_id`, `points` |
| `GET /tracks`, `GET /tracks/{id}` | Получить треки; список отсортирован от новых к старым, фильтры `artist_id`, `album_id` |
| `PATCH /tracks/{id}` | Изменить `name`, `points` |
| `DELETE /tracks/{id}` | Удалить трек, если он не используется вопросами |
| `GET /downloads`, `GET /downloads/{id}` | Получить загрузки; список отсортирован от новых к старым, фильтры `status`, `track_id` |
| `POST /downloads/{id}/retry` | Повторить ошибку или назначить `source_type`, `source_uri` задаче `manual` |
| `GET /downloads/{id}/file` | Получить полный исходный файл готовой загрузки |
| `GET /settings`, `PATCH /settings` | Прочитать настройки или частично изменить их |
| `GET /genius-quota` | Последний наблюдавшийся лимит Genius или `null`, если данных ещё нет |
| `POST /genius-quota/refresh` | Проверить лимит одним запросом к официальному API Genius |
| `POST /quiz-packs` | Составить пакет: `name`, необязательные `description`, `tags`, `artist_tag` |
| `GET /quiz-packs`, `GET /quiz-packs/{id}` | Получить список или пакет со всеми раундами и вопросами |
| `PATCH /quiz-packs/{id}` | Частично изменить `name`, `description`, `tags` |
| `DELETE /quiz-packs/{id}` | Удалить пакет, его раунды и вопросы |
| `GET /quiz-packs/{id}/questions/{number}/audio` | Получить MP3-фрагмент по сквозному номеру вопроса, начиная с 1 |

Списки возвращают JSON-массив; `limit=1..200` (по умолчанию 50), `offset>=0`.
Points — целое число 0..100, по умолчанию 100. Неизвестные JSON-поля отклоняются.
Ошибки имеют вид `{"error":"сообщение"}`: `400` — данные формы, `404` — объект/аудио не найдено,
`409` — конфликт ссылок/состояния, `422` — нельзя собрать ни одного полного раунда,
`500` — внутренняя ошибка, `504` — таймаут. Создание возвращает `201`, DELETE — `204`.

Состояние `processing` нельзя менять вручную; запрос вернёт `409`. Поле `error` сохраняется
при переводе в `manual`. Лимит отображает данные последнего ответа Genius, а время сброса
вычисляется из заголовка `X-RateLimit-Reset`; после предполагаемого сброса показатель может устареть.

Примеры изменения настроек и ручного источника:

```json
{"k_parse":0.2,"download_workers":2,"round_types":["artist_by_track","artist_by_cover","track_vowels","artist_by_logo","artist_initial","artist_by_track","artist_by_cover","track_vowels","artist_by_logo","artist_initial"]}
```

```json
{"source_type":"mp3","source_uri":"https://example.org/song.mp3"}
```

`source_type` для ручного аудио — `mp3` или `youtube`. Поля локального пути и метаданных загрузки
через API не назначаются. В случае совпадения источника с другой задачей возвращается `409`.
Пути `ffmpeg`, `ffprobe`, `yt_dlp` задаются в настройках: в контейнере нужны Linux-пути,
при локальном запуске — имена в PATH или абсолютные Windows-пути.
Новые настройки применяются к следующим операциям; запущенный импорт использует свой снимок настроек.

## Генерация и звук

Пять обработчиков раундов: `artist_by_track`, `artist_by_cover`, `track_vowels`,
`artist_by_logo`, `artist_initial`. Список из десяти типов настраивается в БД, по умолчанию
эта последовательность повторяется дважды. Каждый сохранённый раунд содержит ровно 10 вопросов.
Если данных меньше, сохраняются только полные раунды; при 17 подходящих исполнителях — один раунд.
Если очередной тип раунда не набирает 10 вопросов, сборка заканчивается на предыдущем полном раунде.

Исполнитель, альбом и трек выбираются тремя SQL-запросами с относительными весами Points.
Нулевые оценки исключают соответствующую ветку, исполнитель не повторяется во всём пакете.
Старая SUM-формула и коэффициенты `kArtist/kAlbum/kTrack` не используются.
Для звуковых раундов требуется готовый MP3 с известной длительностью, для визуальных — готовое изображение.
Треки без альбома хранятся в каталоге, но не участвуют в трёхступенчатом выборе.
Фильтр `artist_tag` выбирает исполнителей с одним указанным тегом; `tags` — метки самого пакета.

Вопрос хранит исходный `sound_download_id` и неизменяемые границы `trackStartSec`, `trackFinishSec`.
Если запись длится до 30 секунд включительно, границы — `0` и её длительность. Иначе выбирается
случайное начало так, чтобы весь 30-секундный интервал находился внутри записи.
Повторные запросы возвращают тот же фрагмент. Аудио-ручка использует ffmpeg, отдаёт `audio/mpeg`
и поддерживает HTTP Range через стандартный файловый обработчик. Из ID3 отрывка удаляется ответ.
Для вопроса без звука возвращается `404`. Исходные файлы сохраняют теги названия, исполнителя и альбома.

Изображения исполнителей находятся в `images/artists`, обложки — в `images/albums`,
полные записи — в `music/tracks`. Фрагменты создаются при первом запросе и кэшируются в `music/clips`.
Удаление пакета удаляет записи БД; исходные файлы и кэш автоматически не удаляются.
Это позволяет не затронуть используемые другими пакетами медиа; очистку диска можно добавить отдельно.

## Архитектура и проверки

`internal/domain` — модели и настройки; `internal/store` — репозитории, SQL и Unit of Work;
`internal/source` — адаптеры Genius/MusicBrainz; `internal/service` — бизнес-операции и работники;
`internal/httpapi` — формы HTTP и маршруты. Сетевые запросы и ffmpeg выполняются вне транзакций БД.
Очередь использует `FOR UPDATE SKIP LOCKED`, срок захвата и до трёх попыток скачивания.
`context.Context` останавливает сетевые запросы и дочерние процессы; при остановке сервис ждёт работников.

```powershell
go test ./...
golangci-lint run --config .golang-ci.yaml
go build ./cmd/quiz

# Интеграционные тесты в изолированных схемах существующей БД:
$env:TEST_DATABASE_URL='postgres://quiz:quiz@127.0.0.1:15432/quiz?sslmode=disable'
go test ./... -count=1

# Linux, PostgreSQL, ffmpeg и race detector в контейнере:
docker compose --profile test run --build --rm test
```

Без `TEST_DATABASE_URL` интеграционные тесты пропускаются; медиатесты требуют ffmpeg/ffprobe.
На Windows `go test -race` дополнительно требует совместимый C-компилятор; контейнерный тест
включает его. Настоящие вызовы Genius требуют пользовательского токена; автоматические тесты
используют локальные HTTP-серверы с фиксированными ответами, а не доступ к чужому каталогу.

Вопрос содержит `answer_info` — сохранённые при генерации имя исполнителя (`artist`), название трека (`track`) и альбома (`album`). Для старых вопросов эти сведения заполняются из каталога при миграции. Подсказка с гласными скрывает содержимое круглых скобок; первая буква исполнителя определяется без начального артикля The.
