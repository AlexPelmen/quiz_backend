# Музыкальные квизы

Go + Gin + PostgreSQL. Сервис хранит музыкальный каталог, импортирует метаданные YouTube Music, Genius и MusicBrainz,
готовит задания на скачивание изображений и MP3 и составляет квиз-пакеты.
Доступ к API защищён сессией пользователя и правами на разделы; по умолчанию HTTP и PostgreSQL доступны только локально.

## Запуск

Для запуска нужен Docker Desktop с Linux-контейнерами. Для операций Genius добавьте токен из https://genius.com/api-clients.

```powershell
Copy-Item .env.example .env
# Запишите GENIUS_ACCESS_TOKEN в .env.
docker compose up -d --build
```

После первого запуска создайте администратора в базе, где ещё нет пользователей:

```powershell
docker compose run --rm --no-deps --entrypoint /app/create-admin api -login ADMIN_LOGIN -password ADMIN_PASSWORD -name "Администратор"
```

Команда принимает пароль параметром: он может остаться в истории команд и быть виден в списке процессов. Используйте отдельный пароль и очистите историю команд при необходимости. Повторный запуск при наличии любого пользователя запрещён. Пароли хранятся как bcrypt-хеши с индивидуальной солью, сессия — случайный токен с хранением только его хеша в БД, сроком 24 часа и отзывом при смене пароля. При публикации через HTTPS установите `AUTH_COOKIE_SECURE=true` и используйте HTTPS на всём внешнем доступе. В настройках ролей `admin` имеет все права, `moderator` — игру, профиль и модерацию обложек, `player` — игру и профиль; дополнительные разделы назначаются отдельно. Делегированный управляющий не может выдавать права шире собственных или изменять администратора. Последнего администратора нельзя удалить или лишить роли.

API: `http://127.0.0.1:8080`. Проверки: `GET /health`, `GET /ready`.
SQL-миграции встроены в бинарник и применяются при запуске. PostgreSQL хранится в Docker-томе,
медиатека — в папке `../media`, подключённой к `/app/data`; путь можно переопределить QUIZ_MEDIA_DIR.
`docker compose down` останавливает сервисы, сохраняя данные.

Для запуска Go-приложения на ПК нужны Go 1.26+, PostgreSQL 17+, `yt-dlp`, `ffmpeg` и `ffprobe`
в PATH; для полной поддержки YouTube нужен Node.js 22+ (или Deno/Bun, выбирается через
`yt_dlp_js_runtime`). Для импорта YouTube Music установите `ytmusicapi==1.12.3` в Python 3.10+
и задайте путь к этому Python в `yt_music_python`. Значение по умолчанию — `python3`,
на Windows обычно используется `python` или абсолютный путь. Docker-образ включает эти зависимости.

Для авторизации YouTube можно задать переменную окружения `YTDLP_COOKIES_FILE` с путём к файлу cookies в формате Netscape. Файл остаётся вне настроек API; для каждой загрузки создаётся временная копия, поскольку yt-dlp может обновлять файл. При совместном запуске из корня используйте дополнительный compose-файл `compose.cookies.yaml` и переменную `YOUTUBE_COOKIES_FILE` с абсолютным путём на хосте. Cookies являются данными сессии и не должны попадать в Git.
Утилиты запускаются напрямую через `exec.CommandContext`, поэтому PowerShell-функция
или алиас без соответствующего исполняемого файла не подходят. На текущем ПК EXE найдены.

```powershell
docker compose up -d db
$env:DATABASE_URL='postgres://quiz:quiz@127.0.0.1:15432/quiz?sslmode=disable'
$env:GENIUS_ACCESS_TOKEN='ваш-токен'
go run ./cmd/quiz
```

Локальный запуск Go не читает `.env` автоматически. ENV: `DATABASE_URL` обязателен,
`HTTP_ADDR` по умолчанию `127.0.0.1:8080`, `GENIUS_ACCESS_TOKEN` нужен для импорта Genius и двух загрузчиков Genius.
Остальная эксплуатационная конфигурация хранится в единственной записи таблицы `settings`.

## Рабочий сценарий

```powershell
$base='http://127.0.0.1:8080/api/v1'
$artist=Invoke-RestMethod "$base/artists" -Method Post -ContentType 'application/json' `
  -Body '{"name":"Queen","tags":["rock"]}'
$run=Invoke-RestMethod "$base/parsing-runs" -Method Post
Invoke-RestMethod "$base/parsing-runs/$($run.id)"
Invoke-RestMethod "$base/albums?artist_id=$($artist.id)"
Invoke-RestMethod "$base/tracks?artist_id=$($artist.id)"
$jobs=Invoke-RestMethod "$base/downloads?status=created"
$selected=@($jobs | Where-Object file_type -eq 'mp3' | Select-Object -First 1 -ExpandProperty id)
if ($selected.Count) {
  Invoke-RestMethod "$base/downloads/start" -Method Post -ContentType 'application/json' `
    -Body (@{downloader='yt_music';download_ids=$selected} | ConvertTo-Json -Compress)
}

# Для пакета нужен хотя бы один полный раунд: 10 разных исполнителей с подходящими медиа.
$pack=Invoke-RestMethod "$base/quiz-packs" -Method Post -ContentType 'application/json' `
  -Body '{"name":"Рок-квиз","artist_tag":"rock","tags":["rock"]}'
Invoke-WebRequest "$base/quiz-packs/$($pack.id)/questions/1/audio" -OutFile question-1.mp3
```

Добавление исполнителя не начинает импорт. На странице «Парсинг» выберите YouTube Music, Genius
или MusicBrainz. Через API это `POST /api/v1/parsing-runs` с телом `{"provider":"yt_music"}`,
`{"provider":"genius"}` или `{"provider":"musicbrainz"}`. Без тела запускается YouTube Music.
Одновременно может работать один прогон. Для Genius нужен `GENIUS_ACCESS_TOKEN`.

Прогон сначала обрабатывает частичные записи и записи с ошибками, затем новые. Каждый ответ
сохраняется отдельно. Известные ID переиспользуются, заполненные поля сохраняют своё значение.
Сбой запроса после ретраев переводит сущность в `error`, следующий прогон её подберёт.
Если часть данных отсутствует без ошибки, статус будет `partial`. Заполненная карточка получает
`parsed`. Явный `manual` у исполнителя исключает его из очереди.

Цель подборки составляет от одного до пяти студийных альбомов по числу подписчиков YouTube Music.
По умолчанию подбирается один альбом. При 500 тыс., 1 млн, 3 млн и 5 млн лимит увеличивается до 2, 3, 4 и 5 соответственно.
Успешную выборку запоминаем для провайдера, в том числе если она вернула меньше пяти.
Другой провайдер может добрать подборку даже у импортированного исполнителя. Полный CSV-треклист
необязателен и заполняется вручную. Лимит популярных треков составляет от одного до восьми
по числу подписчиков. Новый импорт сохраняет метрики исполнителя и трека из источника.
Для YouTube Music парсер сравнивает счётчики прослушиваний первых 20 треков из подборки
и отбирает самые прослушиваемые в пределах этого лимита. Если счётчик кандидата недоступен,
подборка не подтверждается, а ошибка видна в журнале. Округлённые значения с одинаковым числом
сохраняют исходный порядок. Ранее сохранённые треки не удаляются; в квизе доступны все
подходящие треки с готовой записью, а ручные значения прослушиваний сохраняются.
Кнопка «Повторить» у исполнителя разрешает заново собрать эту подборку при следующем запуске YouTube Music.
Если метрика отсутствует, API возвращает `null`. Аудио и изображения скачиваются отдельно. Новые записи и изображения сохраняются под именами исполнителя и трека или альбома; при совпадении имени добавляется ID загрузки. Недопустимые для файловой системы символы заменяются. Уже сохранённые файлы не переименовываются.

Совместная запись хранится как один трек с несколькими связями с исполнителями.
При повторном импорте известный ID источника связывает существующий трек с новым исполнителем.
Общий каталог показывает трек один раз, а в подборке каждого связанного исполнителя видна та же запись. При удалении исполнителя удаляются его альбомы и треки, не связанные с другими исполнителями; совместные треки сохраняются.

Карточку исполнителя можно создать по одной ссылке YouTube Music: до парсинга она показывается вместо названия, затем заменяется названием из карточки. При поиске исполнителя по названию используется первый результат YouTube Music. Если месячная
аудитория недоступна, вместо неё используется удвоенное количество подписчиков, если оно известно.

MusicBrainz сопоставляет написания с учётом пробелов, знаков, латинской диакритики и распространённой
русской транслитерации; при отсутствии совпадений повторяет поиск по нормализованному имени. Среди
совпадений одного качества выбирается первый результат MusicBrainz: порядок поиска учитывает популярность,
но не является точным числом слушателей и может привести к выбору другого одноимённого исполнителя.

В карточке исполнителя можно указать `yt_music_url` со страницей `https://music.youtube.com/@...`
или `https://music.youtube.com/channel/UC...`. Если YouTube Music ID ещё не известен, при следующем
запуске парсер определит его по ссылке; неверная ссылка или страница другого типа приведёт к ошибке.
Для известных ID ссылка формируется автоматически. Ссылка не изменяет уже сохранённый ID.

### Ретраи, журнал и остановка

Настройки доступны в админке и через `GET/PATCH /api/v1/settings`.

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `source_429_retries` | 3 | Число повторов запроса после ошибки в прогоне провайдера, от 0 до 10 |
| `source_429_delay_seconds` | 1 | Базовая задержка, умножается на номер повтора |
| `source_429_max_delay_seconds` | 3 | Верхняя граница задержки. Если сервер требует ждать дольше через Retry-After, короткие повторы прекращаются |
| `parser_stop_failures` | 10 | Порог одинаковых ошибок после ретраев подряд на двух и более сущностях |

Успешный запрос сбрасывает серию, включая ответ без совпадений. При автоматической остановке
все сохранённые данные остаются в каталоге. В таблице прогонов видны провайдер, заполненные поля,
новые альбомы и треки, ошибки запросов и причина остановки. Подробности запросов доступны в журнале
и через `GET /api/v1/parsing-runs/{id}/events`.

«Очистка альбомов» показывает записи вне полной подборки из рейтинга YouTube Music.
Альбомы из готовых квизов защищены, связанные треки остаются
в каталоге.

### Ручной запуск загрузок

Парсинг готовит задания в состоянии `created`. На странице «Загрузки» отметьте строки и нажмите
кнопку нужного загрузчика. Только выбранные задания переходят в `pending`. Задания, появившиеся
после запуска, ждут следующего выбора. Для изображений есть отдельная кнопка.
Кнопки «Все» запускают все совместимые задания в состоянии `created` одного типа на всех страницах;
задачи с ошибками, выполняемые и завершённые при этом не перезапускаются.

| Загрузчик | Источник |
| --- | --- |
| `yt_music` | Ссылка YouTube Music и yt-dlp |
| `hitmo` | Поиск «исполнитель - трек» через `hitmo_url` (по умолчанию `https://rus.hitmos.fm`). Нужна известная длительность, допуск ±1 секунда. При 403 проверьте доступ из вашей сети |
| `genius_youtube` | Ссылка YouTube из карточки Genius и yt-dlp |
| `genius_short` | Доступное короткое аудио из плеера карточки Genius |
| `image` | Сохранённая ссылка на логотип или обложку |

Задание с ошибкой можно повторно выбрать с любым подходящим загрузчиком. Прямую ссылку можно
запустить через форму задания. После временного сбоя воркер повторяет уже запущенную операцию
до трёх попыток. Готовые полные записи имеют приоритет над превью при генерации квиза.

## HTTP API

Все пути ниже имеют префикс `/api/v1`. Формальная спецификация: [docs/openapi.json](docs/openapi.json).
JSON использует `snake_case`, кроме явно согласованных `trackStartSec` и `trackFinishSec`.

| Метод и путь | Назначение |
| --- | --- |
| `POST /artists` | Создать исполнителя: `name`, необязательные `tags`, `yt_plays`, `yt_subs`, `excluded_from_quiz` |
| `GET /artists`, `GET /artists/{id}` | Получить исполнителей. Фильтры списка: `name` (часть названия без учёта регистра), `tag`, `status` |
| `PATCH /artists/{id}` | Изменить поля исполнителя или статус на `manual` / `created` |
| `POST /artists/{id}/image` | Загрузить или заменить изображение исполнителя |
| `DELETE /artists/{id}` | Удалить исполнителя и каталог, если нет ссылок из вопросов |
| `POST /artists/{id}/retry` | Вернуть обработанного, ошибочного или ручного исполнителя в `created` |
| `POST /parsing-runs` | Запустить импорт асинхронно, ответ `202` |
| `GET /parsing-runs`, `GET /parsing-runs/{id}` | Состояние и счётчики импорта |
| `POST /parsing-runs/{id}/stop` | Остановить запуск после текущего исполнителя; ожидающий запуск снимается сразу |
| `POST /downloads/start` | Запустить 1–200 выбранных `download_ids` либо все ожидающие с `all_waiting: true`, либо подходящие выбранному фильтру с `all_matching: true`, необязательными `status` и `excluded_ids`. Ответ содержит `queued`. Несовместимый или занятый выбранный ID возвращает `409` |
| `POST /albums` | Создать альбом: `name`, `artist_id`, необязательные `yt_plays`, `excluded_from_quiz`, `release_date`, `track_list` |
| `GET /albums`, `GET /albums/{id}` | Получить альбомы; фильтры `artist_id`, `status` |
| `PATCH /albums/{id}` | Изменить поля альбома, включая дату, треклист и метрики |
| `POST /albums/{id}/cover` | Загрузить или заменить обложку альбома |
| `GET /album-guessing` | Очередь модерации готовых обложек; фильтр `status`: `pending`, `approved`, `rejected`; `shuffle` — число от 0 до 4294967295 для случайного порядка с чередованием исполнителей |
| `GET /albums/{id}/guessing-preview?cover_id=…` | Исходная обложка в PNG для редактора модерации |
| `PUT /albums/{id}/guessing` | Сохранить решение и маски для указанной версии обложки; возвращает `204` |
| `DELETE /albums/{id}` | Удалить альбом; треки остаются без привязки к нему |
| `POST /tracks` | Создать трек: `name`, `artist_id`, необязательные `album_id`, `duration_seconds`, `yt_plays`, `excluded_from_quiz` |
| `GET /tracks/{id}/artists` | Получить всех исполнителей трека, основной исполнитель указан первым |
| `GET /tracks`, `GET /tracks/{id}` | Получить треки. Фильтры `artist_id`, `album_id`, `status` каталога и `audio_status` |
| `PATCH /tracks/{id}` | Изменить поля трека. Для удаления связи с альбомом передать нулевой UUID в `album_id` |
| `POST /tracks/{id}/audio` | Загрузить основную запись трека в формате MP3 |
| `DELETE /tracks/{id}` | Удалить трек, если он не используется вопросами |
| `POST /storage/actions` | Действия `attach` или `delete` над 1–200 путями. Привязка требует единственного совпадения и не заменяет существующие изображения. Ответ содержит ошибки отдельных файлов |
| `GET /storage` | Сводка файлов в `storage_dir` и относительные пути файлов без ссылок из каталога или квиза; временные скрытые каталоги и символьные ссылки исключены |
| `GET /downloads`, `GET /downloads/{id}` | Получить загрузки; фильтры `status`, `track_id`, `file_type` (`mp3` или `image`). В списке трека ручные файлы показываются первыми, далее порядок от новых к старым |
| `POST /downloads/{id}/retry` | Запустить прямую ссылку `source_type`, `source_uri` для ожидающей или ошибочной задачи |
| `GET /downloads/{id}/file` | Получить полный исходный файл готовой загрузки |
| `GET /settings`, `PATCH /settings` | Прочитать настройки или частично изменить их |
| `GET /genius-quota` | Последний наблюдавшийся лимит Genius или `null`, если данных ещё нет |
| `POST /genius-quota/refresh` | Проверить лимит одним запросом к официальному API Genius |
| `POST /quiz-packs` | Составить пакет: `name`, необязательные `description`, `tags`, `artist_tag` |
| `GET /quiz-packs`, `GET /quiz-packs/{id}` | Получить список или пакет со всеми раундами и вопросами |
| `PATCH /quiz-packs/{id}` | Частично изменить `name`, `description`, `tags` |
| `DELETE /quiz-packs/{id}` | Удалить пакет, его раунды и вопросы |
| `GET /quiz-packs/{id}/questions/{number}/audio` | Получить MP3-фрагмент по сквозному номеру вопроса, начиная с 1 |
| `GET /quiz-packs/{id}/questions/{number}/cover` | Получить PNG с масками для вопроса по обложке; `404`, если обложка недоступна или не одобрена |
| `POST /quiz-rounds/{id}/results` | Сохранить результат прохождения раунда и начислить показы и угадывания; возвращает `204` |
| `GET /tags` | Получить полный справочник тегов (`id`, `name`) |
| `POST /tags` | Создать тег по полю `name` |
| `PATCH /tags/{id}` | Переименовать тег у исполнителей, альбомов, треков и пакетов |
| `DELETE /tags/{id}` | Удалить неиспользуемый тег; используемый возвращает `409` |

Списки возвращают JSON-массив; `limit=1..200` (по умолчанию 50), `offset>=0`.
Каталог сортируется до разбиения на страницы. `sort` принимает `name`, `yt_plays`, `created_at`, `status`,
а также `audio_status` у треков и `release_date` у альбомов.
`order=asc|desc` задаёт направление, по умолчанию `asc` при указанном `sort`.
Без `sort` исполнители и треки идут от новых к старым, альбомы — от старых к новым.
Статус аудио трека отражает наиболее готовую запись в порядке
`finished`, `processing`, `pending`, `created`, `errored`, `manual`. При отсутствии источников возвращается `missing`.

Методы загрузки файлов принимают байты в теле с `Content-Type: application/octet-stream`
и возвращают `201` с объектом Download (`source_type: upload`, `status: finished`).
Максимальный размер — меньшее из `max_download_bytes` и 100 МиБ.
Поддерживаются MP3 для треков и PNG, JPEG, GIF, WebP, BMP, ICO для изображений.
Импорт сохраняет загруженные вручную изображения и изменённую дату альбома.
Новые вопросы используют последний загруженный вручную MP3. Сохранённые вопросы продолжают использовать свои файлы.

`asked` и `guessed` доступны только для чтения. `excluded_from_quiz` исключает запись из подбора.
Статус `manual` показывает, что нужно заполнить поля из `missing_fields` или исправить медиа.
Неизвестные JSON-поля отклоняются.
Ошибки имеют вид `{"error":"сообщение"}`: `400` — данные формы, `404` — объект/аудио не найдено,
`409` — конфликт ссылок/состояния, `422` — нельзя собрать ни одного полного раунда,
`500` — внутренняя ошибка, `504` — таймаут. Создание возвращает `201`, DELETE — `204`.

Состояние `processing` нельзя менять вручную; запрос вернёт `409`. Поле `error` сохраняется
при переводе в `manual`. Лимит отображает данные последнего ответа Genius, а время сброса
вычисляется из заголовка `X-RateLimit-Reset`; после предполагаемого сброса показатель может устареть.

Примеры изменения настроек и ручного источника:

```json
{"quiz_guess_rate_enabled":true,"quiz_guess_rate_asked_threshold":5,"download_workers":2}
```

```json
{"source_type":"mp3","source_uri":"https://example.org/song.mp3"}
```

`source_type` для ручного аудио — `mp3` или `youtube`. Поля локального пути и метаданных загрузки
через API не назначаются. В случае совпадения источника с другой задачей возвращается `409`.
Пути `ffmpeg`, `ffprobe`, `yt_dlp` задаются в настройках: в контейнере нужны Linux-пути,
при локальном запуске — имена в PATH или абсолютные Windows-пути.
Новые настройки применяются к следующим операциям; запущенный импорт использует свой снимок настроек.

## Генерация и звук

В базовой последовательности пять типов раундов: `artist_by_track`, `artist_by_cover`, `track_vowels`,
`artist_by_logo`, `artist_initial`. Список из десяти типов настраивается в БД, по умолчанию
эта последовательность повторяется дважды. Каждый сохранённый раунд содержит ровно 10 вопросов.
Если данных меньше, сохраняются только полные раунды; при 17 подходящих исполнителях — один раунд.
Если очередной тип раунда не набирает 10 вопросов, сборка заканчивается на предыдущем полном раунде.

При создании пакета можно передать `difficulty` (`easy`, `medium`, `hard`) и `round_types` — непустой
список уникальных типов в порядке игры. Если для явно выбранного раунда не хватает кандидатов, API
возвращает 422 с его типом. Для загрузки обложки отправьте тот же запрос
как `multipart/form-data` с JSON в поле `pack` и изображением в поле `cover`. Ответ содержит
`cover_download_id`; изображение выдаётся обычным маршрутом скачивания.

`artist_by_albums` показывает до десяти разных названий альбомов, выбранных с учётом сложности. В `artist_cities` последняя буква
предыдущего исполнителя совпадает с первой буквой следующего, в `artist_alphabet` первые буквы строго
возрастают. Оба раунда используют латинскую транслитерацию. «Города» пропускают начальные
артикли The, A и An, а названия с цифрами на краях исключают из цепочки.
В `artist_growth` строго возрастает число букв в исходном названии исполнителя.
В этих трёх раундах игра использует готовые аудиофрагменты.

Узнаваемость вычисляется отдельно для допустимых исполнителей, альбомов и треков.
Для треков порядок всегда определяется прослушиваниями. Для исполнителей и альбомов
по умолчанию при `asked > 5` берётся доля `guessed / asked`. В остальных случаях берётся
`yt_plays / max(yt_plays)` по текущим кандидатам. Порог меняется через `quiz_guess_rate_asked_threshold`.
При `quiz_guess_rate_enabled=false` используются только прослушивания. Неизвестные прослушивания
и нулевой максимум дают оценку 0.

Кандидаты сортируются по убыванию оценки. Нормальная кривая взвешивает позиции, её центр равен
`0.2 × N`, `0.5 × N` или `0.8 × N` для лёгкого, среднего и сложного пакета, отклонение — `0.15 × N`.
Статус `manual` допускает участие при наличии данных для раунда. Для звука нужен готовый MP3
с известной длительностью, связь трека с альбомом необязательна. Исполнитель не повторяется в пакете.
В раунде `track_vowels` нужна хотя бы одна русская или английская согласная за пределами пометок в скобках.
В подсказке согласные пропускаются, буквы показываются строчными.
Для обложки нужен альбом с готовой и одобренной версией обложки, для логотипа — готовое изображение исполнителя.

Модерация хранит решение `approved`, идентификатор проверенного файла `cover_download_id` и до 32
прямоугольников `rectangles`. Два угла `x1,y1,x2,y2` задаются целыми числами от 0 до 10000
относительно ширины и высоты изображения, от верхнего левого угла. Пустой список разрешён для обложки без подсказок.
Редактор и игровой маршрут используют одинаковый растр PNG. Поддерживаются PNG, JPEG, GIF (первый кадр), BMP и WebP до 4096×4096.

Маски накладываются на сервере при каждом запросе игры; файлы с масками не сохраняются. Вопросы по обложкам
не передают ID оригинала и ID альбома в игровом JSON. Миграция убирает ссылки на оригиналы из старых пакетов.
Запрет или замена обложки немедленно делает её недоступной и в старых пакетах, пока текущую версию не одобрят.
Каталог и редактор по-прежнему предоставляют исходные обложки. API не разделяет доступ игроков и модераторов.
Фильтр `artist_tag` выбирает исполнителей с одним указанным тегом; `tags` — метки самого пакета.
Существующие теги исполнителей и пакетов переносятся в справочник при миграции. Старые клиенты,
передающие новые имена тегов в этих полях, также добавляют их в справочник.
Теги также доступны при создании и изменении альбомов и треков.

Вопрос хранит исходный `sound_download_id` и неизменяемые границы `trackStartSec`, `trackFinishSec`.
Если запись длится до 30 секунд включительно, границы — `0` и её длительность. Иначе выбирается
случайное начало так, чтобы весь 30-секундный интервал находился внутри записи.
Повторные запросы возвращают тот же фрагмент. Аудио-ручка использует ffmpeg, отдаёт `audio/mpeg`
и поддерживает HTTP Range через стандартный файловый обработчик. Из ID3 отрывка удаляется ответ.
Для вопроса без звука возвращается `404`. Исходные файлы сохраняют теги названия, исполнителя и альбома.

Изображения исполнителей находятся в `images/artists`, обложки — в `images/albums`,
полные записи — в `music/tracks`. Фрагменты создаются при первом запросе и кэшируются в `music/clips`.
Удаление пакета удаляет записи БД; исходные файлы и кэш автоматически не удаляются.
Это позволяет не затронуть используемые другими пакетами медиа; очистку диска можно добавить отдельно.

## Счётчики и миграция каталога

Перед обновлением существующей установки сделайте резервную копию PostgreSQL. Обновляйте backend
и админку вместе. Миграция `013_catalog_metrics.sql` переносит владельцев треков и альбомов
в таблицы связей, сохраняет пакеты, результаты и ссылки на файлы. Незавершённые активные
загрузки переходят в `created` и ждут ручного запуска.

Старые оценки сохраняются в `legacy_catalog_popularity`. Для дробного Points миграция записывает
`asked = 3` и `guessed = round(points × 3 / 100)`. Целый Points даёт нулевые счётчики.
Points = 0 переносится в `excluded_from_quiz`. Уже сохранённые ответы остаются в истории.

Клиент отправляет `attempt_id`, итог `r` из `n` и отметку `answers` для каждого UUID вопроса.
В одной транзакции сохраняется попытка и увеличивается `asked` у исполнителя и цели вопроса
(трека или альбома), если она есть. Правильный ответ также увеличивает `guessed`.
Повтор с теми же ответами возвращает `204` без начисления, изменение отметок в той же попытке
возвращает `409`. Удаление пакета удаляет историю его попыток, начисленные счётчики сохраняются.

## Архитектура и проверки

`internal/domain` — модели и настройки; `internal/store` — репозитории, SQL и Unit of Work;
`internal/source` — адаптеры YouTube Music, Genius, MusicBrainz и Hitmo; `internal/service` — бизнес-операции и работники;
`internal/httpapi` — формы HTTP и маршруты. Сетевые запросы и ffmpeg выполняются вне транзакций БД.
Очередь использует `FOR UPDATE SKIP LOCKED`, срок захвата и до трёх попыток скачивания.
`context.Context` останавливает сетевые запросы и дочерние процессы; при остановке сервис ждёт работников.

```powershell
go test ./...
golangci-lint run --config .golang-ci.yaml
go build ./cmd/quiz

# Интеграционные тесты в изолированных схемах существующей БД:
$env:TEST_DATABASE_URL='postgres://quiz:quiz@127.0.0.1:15432/quiz?sslmode=disable'
go test ./... -count=1

# Linux, PostgreSQL, ffmpeg и race detector в контейнере:
docker compose --profile test run --build --rm test
```

Без `TEST_DATABASE_URL` интеграционные тесты пропускаются; медиатесты требуют ffmpeg/ffprobe.
На Windows `go test -race` дополнительно требует совместимый C-компилятор; контейнерный тест
включает его. Настоящие вызовы Genius требуют пользовательского токена; автоматические тесты
используют локальные HTTP-серверы с фиксированными ответами, а не доступ к чужому каталогу.

Вопрос содержит `answer_info` — сохранённые при генерации имя исполнителя (`artist`), название трека (`track`) и альбома (`album`). Для старых вопросов эти сведения заполняются из каталога при миграции. Подсказка с гласными скрывает содержимое круглых скобок; первая буква исполнителя определяется без начального артикля The.
